# AI Career Copilot

AI-powered resume-to-job analysis using a Vercel serverless backend and Google's Gemini API. The original APNOAI starter's navy/orange visual direction and resume/job-description workflow are retained, with PDF upload, skill-gap analysis, downloadable PDF reports, and local analysis history added.

## Features

- Paste resume text or upload a text-based PDF (PDF.js, up to 8 MB / 20 pages).
- Analyze a resume against a job description with Gemini structured JSON output.
- Explainable estimated compatibility score with four score dimensions.
- Matching skills, missing skills with priority, missing keywords, improvements, and a learning roadmap.
- Downloadable PDF report.
- Browser-local history (up to 20 records); original resume and job-description text are not saved to history.
- Gemini API key remains on the server in `GEMINI_API_KEY`.

## Requirements

- Node.js 20+
- A Google AI Studio Gemini API key
- A Vercel account and GitHub account

## Run locally

1. Open this folder in VS Code.
2. In a terminal, run:

   ```bash
   npm install
   ```

3. Copy `.env.example` to `.env` and put your newly generated key in `GEMINI_API_KEY`. Never commit `.env`.
4. Run:

   ```bash
   npm run dev
   ```

5. Open the local URL printed by Vercel CLI (usually `http://localhost:3000`). Do not open `public/index.html` directly with `file://`; the `/api/analyze` serverless endpoint must be running.

## Deploy to Vercel

1. Push this project to a new GitHub repository. Keep `.env` out of Git.
2. In Vercel, choose **Add New → Project**, import the repository, and deploy.
3. Before the production deployment, open **Project → Settings → Environment Variables**.
4. Add `GEMINI_API_KEY` with your newly generated Gemini key. Optionally add `GEMINI_MODEL` with a model enabled for your API key (default: `gemini-3.8-flash`).
5. Apply the variables to Production and Preview as needed, then redeploy. Environment variable changes apply to new deployments, not already-created deployments.
6. Open the Vercel URL in an incognito/private window and test a real resume and job description.

## Important security and privacy notes

- If an API key was ever pasted into client-side HTML or shared in a screenshot, revoke it and create a new key.
- Never put `GEMINI_API_KEY` in `public/index.html`, frontend JavaScript, GitHub, or a `NEXT_PUBLIC_` variable.
- The API endpoint enforces POST, same-origin browser requests, input length limits, and server-side API key access. This is an internship/demo baseline, not a complete abuse-prevention system. For a public production service, add authentication, persistent rate limiting (for example Upstash Redis), usage monitoring, and an explicit privacy/retention policy.
- Resume text is sent to Google Gemini for analysis. The app does not store the raw resume or job description in local history. Analysis results are stored in localStorage on the current browser and can be cleared by the user. Avoid uploading sensitive personal information unless you are comfortable with the provider's applicable data terms.
- PDF.js extracts selectable text in the browser. Scanned/image-only PDFs require OCR and are not supported by this version.
- The compatibility score is generated by an AI rubric and is not a real ATS score, hiring guarantee, or employer decision.

## Test checklist

- [ ] Missing resume or job description shows validation feedback.
- [ ] A text-based PDF fills the resume box.
- [ ] A scanned PDF shows a useful extraction error.
- [ ] Analyze returns a score, strengths, skill gaps, and improvements.
- [ ] Invalid/missing Gemini key produces a readable error without exposing the key.
- [ ] Download PDF produces a readable report.
- [ ] Refreshing the page retains local analysis history.
- [ ] Deleting one history item and clearing all history work.
- [ ] Browser devtools Network tab shows the browser calls `/api/analyze`, not Google Gemini directly.
- [ ] GitHub source contains no API key or `.env` file.
